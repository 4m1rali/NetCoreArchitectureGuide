# Приложение C — Часто задаваемые вопросы (FAQ)

---

## Общие вопросы

### В: Можно ли объединить пропускную способность 3× 100Mbps в 300Mbps для одной загрузки?

**О:** Нет. Load balancing распределяет **между соединениями**, а не внутри одного соединения. Одна загрузка использует один WAN (50–100Mbps). Но 10 одновременных загрузок могут задействовать все 3 WAN (~300Mbps суммарно).

### В: Какой метод использовать?

**О:** Для NAT-сред (большинство развёртываний): **PCC + Failover**. Для routed public IP без NAT: **ECMP + Failover**. Для ISP с собственным ASN: **BGP**.

### В: Поддерживает ли MikroTik настоящий link bonding как 802.3ad?

**О:** Нет нативного L2 bonding между ISP. PCC обеспечивает **логический** load balancing на L3/L4. Для настоящего L2 bonding оба конца должны его поддерживать (редко у ISP).

## PCC

### В: Почему распределение PCC 70/30 вместо 50/50?

**О:** PCC хеширует **новые соединения**. Если большая часть трафика — долгоживущие потоки (streaming), распределение зависит от момента создания соединений. Короткие тесты показывают перекос. Мониторьте в течение часов, а не минут.

### В: Можно ли взвесить PCC для WAN с разной скоростью?

**О:** Да. Используйте classifier buckets: `:10/0` через `:10/6` для 70% на WAN1, `:10/7` через `:10/9` для 30% на WAN2.

### В: Работает ли PCC с IPv6?

**О:** Да. Используйте `/ipv6 firewall mangle` с тем же синтаксисом classifier.

## Failover

### В: Насколько быстрый failover?

**О:** Обычно 3–15 секунд с `check-gateway=ping`. Скрипты Netwatch добавляют 10–30 секунд. BGP failover: 30–90 секунд (hold timer).

### В: Сохранятся ли активные соединения при failover?

**О:** Нет. Соединения на отказавшем WAN обрываются. Новые соединения используют резервный WAN. Это ожидаемое поведение.

### В: Должен ли LTE быть в PCC?

**О:** Как правило **нет**. Используйте LTE только для failover (distance=3), чтобы избежать неожиданных расходов на трафик.

## NAT

### В: Почему NAT ломается с ECMP?

**О:** ECMP per-packet hashing отправляет пакеты одного соединения через разные WAN. Return traffic приходит на неверный WAN, нарушая connection tracking.

### В: Что такое hairpin NAT?

**О:** Позволяет LAN-клиентам обращаться к вашему public IP изнутри сети. См. [Главу 9](../09-advanced-nat-dns/README.md).

## Производительность

### В: CPU роутера на 80% с PCC. Что делать?

**О:** Перейти на CCR, сократить mangle rules, отключить лишнее логирование, убедиться что FastTrack выключен (он всё равно конфликтует с PCC).

### В: Сколько соединений выдерживает RB4011 с PCC?

**О:** ~200 000 активных соединений, ~5 000 новых соединений/секунду с PCC mangle.

## Лицензирование

### В: Какая лицензия нужна для Multi-WAN?

**О:** Level 4 минимум для production. Level 3 подходит только для базового failover. См. [Главу 18](../18-routeros-licensing/README.md).

### В: CHR бесплатный?

**О:** У CHR есть бесплатная лицензия с ограничением 1 Mbps. Платные лицензии ($45–$250) снимают ограничение скорости.

## Troubleshooting

### В: Интернет работает только на одном WAN. PCC не балансирует?

**О:** Проверьте: mangle stats (срабатывают ли правила?), inactive status маршрутов, `passthrough=yes` на marks, FastTrack отключён.

### В: После обновления RouterOS PCC перестал работать?

**О:** RouterOS 7 использует `/routing table` вместо `/routing mark`. См. [Главу 20](../20-migration-upgrade/README.md).
